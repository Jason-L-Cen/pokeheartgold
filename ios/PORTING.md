# 完整原生 iOS 移植目标

用户目标：在已有完整源码和 ROM 的基础上完成尽可能完整的原生 iOS 横屏单屏版，最后整体验收。原型、单张地图或少数系统通过检查不代表达成目标。

## 实现约束

- 游戏代码由原作 C/C++ 直接进行本机编译；平台部分使用 iOS 原生接口。不得把 ARM9/ARM7 CPU 解释器、JIT、DS 宿主或双屏模拟器包装成完成的原生版。
- 尽量复用原作数据、脚本、地图、美术、动画、音乐及音效。用户 ROM 是本地内容与行为对照依据，不上传 ROM 或提取的整套内容包。
- 界面保持 iOS 横屏单屏，保留已确认的战斗两级底栏：主菜单 2×2＋精灵球；招式页四槽＋返回。操作区变化不得删去原作系统、剧情或招式效果。
- 原型的 JSON 存档不得被覆盖或伪装成完整原作存档；接入原作存档时分别保存并明确迁移行为。
- 未移植的平台 API 不得用“成功但什么也不做”的空实现来掩盖；未链接／明确失败的接口必须继续保留为待完成项。
- 内部持续编译、测试和对照原作；用户的整体验收留在完整版本阶段。

## 路线

现有 `App/Game.swift` 是验证用的简化规则。继续为它手写原作全部系统容易遗漏原作行为。完整版本改以原作引擎为核心：

1. 保留原作算法和数据布局，替换 Metrowerks／32 位 DS 平台假设；逐个模块用 Clang 编译成本机代码。
2. 在 `Original/` 接入本机内存、资源文件、调度、计时、输入、存档、图形和声音实现；原作游戏层继续调用原有接口。
3. 接入原作主循环、叠加模块、事件脚本、地图对象及完整战斗流程。叠加模块静态／原生链接，不能执行 ROM 内 ARM 代码。
4. 原版 2D／3D 资源和动画通过原生图形后端渲染；根据当前场景重排单屏界面，保留原作数据和交互语义。
5. 完整流程对照验证后，替换当前原型入口；再进行整体验收。

## 版本与构建记录

源码为美版基线，提供的心金 ROM 是日版汉化。原作源码列出的 267 个资源路径中，日版内容包缺少 `a/2/6/4`；日版消息包含 814 个成员，而源码消息资源还包含美版新增内容。必须继续核查脚本、消息编号与语言编码，不能以“有 ROM”推断所有版本的资源可以直接混用。

已实际发现物种名称消息编号差异：美版源码使用 237，而日版同编号消息只有 29 项，日版物种名称候选位于 232。原作断言暴露了这个差异。当前数据模块检查使用独立的构建参考内容包：沿用 ROM 数据，但物种名等消息使用源码工具生成的 829 组美版消息。原始汉化内容包保持不变；生产版的汉化／美版编号映射尚未解决，不能把参考内容包当作完成的汉化版交付。

本地内容导入和检查：

命名文件也可能包含 DS 程序段或混合资源容器，因此“命名文件已导入”不表示它们都可直接装入完整版本。移植必须识别其资源部分，任何 ARM 代码都不能加载执行。

```sh
python3 ios/tools/import_original_content.py --rom /absolute/path/to/heartgold.nds
python3 ios/tests/check_original_content.py
bash ios/Original/check.sh
```

`OriginalContent/` 和 `build-original*/` 均不进入 Git。`Original/check.sh` 是原作数据模块的内部检查，不代表完整引擎已经链接或完整游戏已经可玩。SDK 头文件中的 DS 硬件地址相关诊断仍待平台后端迁移，不能据此启动原作主循环。

对全部 `src/` C/C++ 编译单元执行 iPhoneOS 编译审计：

```sh
python3 ios/tools/audit_original.py --jobs 4
```

初次审计覆盖 1,121 个单元：944 个生成了 iPhoneOS arm64 对象，177 个编译受阻；另登记 187 个汇编源文件。还发现 1,634 个独立警告位置，包括硬件地址、指针宽度和 ABI 假设。报告位于 `build-original-audit/report.json`，保存输入哈希及每个单元诊断。编译通过不代表已经链接、可运行、渲染正确或内容完整，也不能把这个比例当成游戏完成度。

修复原生运行时对象的指针布局、从 `main.lsf` 生成真实的 129 个模块编号、Wi-Fi 界面运行时布局和原生 C++ 库声明后，第二轮达到 1,004 个通过、117 个受阻。模块编号使用原作编号，不再把链接器符号地址截成 32 位；尚未实现的模块加载接口依然不能执行 ROM 中的 ARM 代码。

单独构建原作数据模块的 iPhoneOS 静态库：

```sh
cmake -S ios/Original -B ios/build-original-device -G Xcode \
  -DCMAKE_SYSTEM_NAME=iOS -DCMAKE_OSX_SYSROOT=iphoneos \
  -DCMAKE_OSX_DEPLOYMENT_TARGET=16.0
cmake --build ios/build-original-device --config Release \
  --target HeartGoldOriginalData -- CODE_SIGNING_ALLOWED=NO -quiet
```

该模块仍未替代当前 App 的简化 `Game.swift`，不能以模块构建通过宣称完整版本交付。

内存初始化已改为执行原作 `Heap_InitSystem`／`Heap_Create`／`Heap_Destroy` 和 SDK 扩展堆。检查使用原版四组初始堆参数，验证两端分配、缩容、子堆销毁与父堆空闲量恢复，以及本机内存区的对齐、边界和嵌套临界区。`tests/environment.c` 只为无通信会话的内部检查提供环境，生产静态库不包含该文件。真实场景的内存预算和完整事件调度仍需继续接入与校准。
