# Original engine UIKit entry

This target runs the compiled original C/C++ engine in UIKit. It is separate from the earlier Swift gameplay prototype in `App/`. The executable contains native arm64 code generated at build time; it does not load a DS CPU interpreter, JIT or WebAssembly module at runtime.

Build after the strict ABI32 audit and native content preparation:

```sh
HG_ABI32_TOOLS=/absolute/path/to/abi32-tools python3 ios/tools/build_original_app.py
HG_ABI32_TOOLS=/absolute/path/to/abi32-tools python3 ios/tools/build_original_app.py --sdk iphoneos
```

The outputs are `ios/build-original-abi32/app-<sdk>/HeartGoldOriginal.app`. Device builds are ad-hoc signed and require a development signing profile before installation on a physical device. The private verified content pack is copied into the bundle; do not commit or redistribute it. The existing Swift target and its resources are untouched.

The game owns one native thread. UIKit queues input under a condition lock, and the owner applies it between display events. Frames are copied into immutable `NSData`; the main thread displays the latest frame without building a callback backlog. Backgrounding clears held input and suspends the owner and display clock. Foregrounding restarts the clock and observer. Scene disconnection requests the existing original reset/drain path before freeing the module. The original 512 KiB save is stored separately at `Application Support/HeartGoldOriginal/heartgold.sav`; prototype JSON saves are not migrated or overwritten.

Original 48 kHz stereo synthesis feeds `AVAudioEngine` through `AVAudioSourceNode`. The game copies borrowed PCM into an owned 8192-frame ring; the render callback consumes it using atomic cursors, without allocating, locking, calling the game, or reading module memory. Playback primes and reprimes after 2048 queued frames (42.67 ms at 48 kHz), adding 21.33 ms of startup/rebuffer latency to cover the measured producer/output-callback phase gap. Queue accounting follows frames actually read, avoiding false overflow from delayed player-completion callbacks. Statistics distinguish rejected frames from playback underruns and observe nonzero PCM before the final mute gain. Ambient audio respects the system's audio policy. Backgrounding and interruptions pause the native sound clock and engine, so resuming does not synthesize the background interval. An interruption without permission to resume, or headphone disconnection, waits for a user button press before resuming. Output failures are reported. New error-returning APIs are used on iOS 27, with iOS 16–26 compatibility paths.

For a runnable UIKit check, build with `--check`, install and launch on an iOS Simulator. After the check finishes, read `Documents/original-app-check.json`, `original-audio-metrics.json` and `original-world-state.json` from the app data container. Checks cover native controls/accessibility, original touch routing, field menu overlays, battle layout transitions, actual Route29 rendering, original nonzero PCM before the final mute gain, pause/resume queue bounds and underruns, interruption state handling, and normal reset cleanup. CHECK-only audio metrics retain the first shortage's callback size, available/read/rendered frames and largest callback; the render callback records atomic values without logging or allocating. This check intentionally stops the engine after testing and forces silent output. Normal test launches before 20:00 Beijing must set `SIMCTL_CHILD_HEARTGOLD_TEST_MUTE=1`. Interruption checks inject notifications rather than physical calls/headsets.

The owner services elapsed PCM at every native display event, before the 30 Hz presentation gate and after drawing. Repeatedly enabling the sound clock advances samples without resetting its fractional remainder; original sound queries alone can be only 30 Hz. Commands still execute through the original sound pump. This reduces presentation-related producer gaps; long owner-thread stalls and device-clock drift still require hardware calibration.
