# Original engine UIKit entry

This target runs the compiled original C/C++ engine in UIKit. It is separate from the earlier Swift gameplay prototype in `App/`. The executable contains native arm64 code generated at build time; it does not load a DS CPU interpreter, JIT or WebAssembly module at runtime.

Build after the strict ABI32 audit and native content preparation:

```sh
HG_ABI32_TOOLS=/absolute/path/to/abi32-tools python3 ios/tools/build_original_app.py
HG_ABI32_TOOLS=/absolute/path/to/abi32-tools python3 ios/tools/build_original_app.py --sdk iphoneos
```

The outputs are `ios/build-original-abi32/app-<sdk>/HeartGoldOriginal.app`. Device builds are ad-hoc signed and require a development signing profile before installation on a physical device. The private verified content pack is copied into the bundle; do not commit or redistribute it. The existing Swift target and its resources are untouched.

The game owns one native thread. UIKit queues input under a condition lock, and the owner applies it between display events. Frames are copied into immutable `NSData`; the main thread displays the latest frame without building a callback backlog. Backgrounding clears held input and suspends the owner and display clock. Foregrounding restarts the clock and observer. Scene disconnection requests the existing original reset/drain path before freeing the module. The original 512 KiB save is stored separately at `Application Support/HeartGoldOriginal/heartgold.sav`; prototype JSON saves are not migrated or overwritten.

Original 48 kHz stereo synthesis feeds `AVAudioEngine` through `AVAudioSourceNode`. The game copies borrowed PCM into an owned 8192-frame ring; the render callback consumes it using atomic cursors, without allocating, locking, calling the game, or reading module memory. Playback primes after 1024 queued frames. Queue accounting follows frames actually read, avoiding false overflow from delayed player-completion callbacks. Statistics distinguish rejected frames from playback underruns and observe nonzero PCM before the final mute gain. Ambient audio respects the system's audio policy. Backgrounding and interruptions pause the native sound clock and engine, so resuming does not synthesize the background interval. An interruption without permission to resume, or headphone disconnection, waits for a user button press before resuming. Output failures are reported. New error-returning APIs are used on iOS 27, with iOS 16–26 compatibility paths.

For a runnable UIKit check, build with `--check`, install and launch on an iOS Simulator. After the check finishes, read `Documents/original-app-check.json`, `original-audio-metrics.json` and `original-world-state.json` from the app data container. Checks cover native controls/accessibility, original touch routing, field menu overlays, battle layout transitions, actual Route29 rendering, original nonzero PCM before the final mute gain, pause/resume queue bounds and underruns, interruption state handling, and normal reset cleanup. This check intentionally stops the engine after testing and forces silent output. Normal test launches before 20:00 Beijing must set `SIMCTL_CHILD_HEARTGOLD_TEST_MUTE=1`. Interruption checks inject notifications rather than physical calls/headsets.

The owner services elapsed PCM at every native display event, before the 30 Hz presentation gate and after drawing. Repeatedly enabling the sound clock advances samples without resetting its fractional remainder; original sound queries alone can be only 30 Hz. Commands still execute through the original sound pump. This reduces presentation-related producer gaps; long owner-thread stalls and device-clock drift still require hardware calibration.

`bash ios/tests/run_original_audio_checks.sh` checks PCM limits/extrema, owned stereo samples, exact offline streaming through concurrent ring wraps, pause/resume continuity and real overflow bounds under AddressSanitizer/UndefinedBehaviorSanitizer and ThreadSanitizer. Its unmuted sample comparisons run only in offline manual-render mode. The ABI32 checks exercise native output callbacks, repeated real-time servicing without new game commands, detachment, explicit/realtime exclusivity and pausing the sound clock.

The field menu reuses original pixels and hitboxes over the wide world. Battle commands use a native bottom 2×2 bar, round ball shortcut and four-move/back layout. Target selection uses four native cards (opponents above, allies below) and Back, reusing original legality, affected groups, nickname/gender glyphs and selection/cancel feedback, with HP and accessibility descriptions. The battle canvas spans the available landscape width; original BG3 text backdrops extend at their tile pitch, with a centered 512-pixel OBJ/3D camera and up to 1024-pixel RGBA output. Original sprite sizes, positions, relative text layout and animations remain in game coordinates. The scene stays present when the command menu is temporarily inactive. Child menus route to their original touch engine, with manual fallback for unsupported menu types.

Passing the covered checks does not prove the complete story, every move/effect or physical-device fidelity. Wide affine/bitmap BG3 backdrop sampling, OBJ mosaic and scanline effects remain incomplete. Some original menus still require the fallback canvas. Earlier playback underruns, long-session clock drift, calls/headsets and route recovery need further investigation/calibration; queue overflow and underrun metrics remain visible. Original soft reset stops this entry instead of automatically rebooting it. Unexpected IRQ/fiber traps still fail fast; other unexpected traps quarantine live module memory to avoid use-after-free of native transfers. Complete flow validation remains required.

Native-host sine/cosine data is generated from the original 4096 assembly pairs; the ABI32 path continues using its verified original data object.

The pool now has a typed four-argument loader, and the area callback explicitly receives the pool and animation instead of relying on their first-member layouts. The pool-list constructor returns its allocated object, arrays use element sizes, and animation allocation derives the map-data extent from the actual object layout.
