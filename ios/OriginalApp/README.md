# Original engine UIKit entry

This target runs the compiled original C/C++ engine in UIKit. It is separate from the earlier Swift gameplay prototype in `App/`. The executable contains native arm64 code generated at build time; it does not load a DS CPU interpreter, JIT or WebAssembly module at runtime.

Build after the strict ABI32 audit and native content preparation:

```sh
HG_ABI32_TOOLS=/absolute/path/to/abi32-tools python3 ios/tools/build_original_app.py
HG_ABI32_TOOLS=/absolute/path/to/abi32-tools python3 ios/tools/build_original_app.py --sdk iphoneos
```

The outputs are `ios/build-original-abi32/app-<sdk>/HeartGoldOriginal.app`. Device builds are ad-hoc signed and require a development signing profile before installation on a physical device. The private verified content pack is copied into the bundle; do not commit or redistribute it. The existing Swift target and its resources are untouched.

The game owns one native thread. UIKit queues input under a condition lock, and the owner applies it between display events. Frames are copied into immutable `NSData`; the main thread displays the latest frame without building a callback backlog. Backgrounding clears held input and suspends the owner and display clock. Foregrounding restarts the clock and observer. Scene disconnection requests the existing original reset/drain path before freeing the module. The original 512 KiB save is stored separately at `Application Support/HeartGoldOriginal/heartgold.sav`; prototype JSON saves are not migrated or overwritten.

Original 48 kHz stereo synthesis now feeds `AVAudioEngine` through `AVAudioPlayerNode`. PCM is copied into separate float buffers before scheduling; audio callbacks update atomic counters and never call the game or read module memory. The output starts after 1024 queued frames and caps pending data at 8192 frames. Its output-monitoring tap requests the SDK's minimum 100 ms buffer, avoiding unnecessary render-ahead pressure from a 200 ms tap. Ambient audio respects the system's audio policy. Backgrounding and interruptions pause the native sound clock and the player, so resuming does not synthesize the background interval. An interruption without permission to resume, or headphone disconnection, waits for a user button press before resuming. Output failures are reported. New error-returning APIs are used on iOS 27, with iOS 16–26 compatibility paths.

For a runnable UIKit check, build with `--check`, install and launch on an iOS Simulator. After about twenty-four seconds, read `Documents/original-app-check.json` and `Documents/original-audio-metrics.json` from the app data container. Its twenty-two checks cover control events, accessibility activation/release, touch bounds, frames, original nonzero PCM reaching the mixer output, bounded audio queues without drops in the opening, pause/resume of both clocks and output, interruption state handling, and normal reset cleanup. This check intentionally stops the engine after testing. Interruption state checks inject notifications; they do not simulate a physical phone call or headset.

`bash ios/tests/run_original_audio_checks.sh` separately checks PCM limits, signed extrema, independent stereo copies and exact 48 kHz offline AVAudioEngine output under AddressSanitizer/UndefinedBehaviorSanitizer. The ABI32 checks exercise native output callbacks, detachment, explicit/realtime exclusivity and pausing the sound clock.

Verified on the iOS 27 iPhone 18 Pro Simulator: original opening graphics and nonzero original audio in the output graph, all twenty-two runtime checks passing. The latest audio snapshots show 4332 queued frames before pause and 4814 after resume, with zero dropped frames in both. This does not verify battles, all music/effects, the complete story, long sessions or physical-device performance and audibility.

Remaining limitations: the canvas currently switches between the original scene and touch menu; the intended contextual landscape interface and custom battle action bar are not connected yet. Long-session clock drift, actual calls/headsets and route recovery need physical-device calibration; the bounded queue records dropped frames rather than allowing unbounded latency. Original soft reset stops this entry instead of automatically rebooting it. Unexpected IRQ/fiber traps still fail fast; other unexpected traps quarantine live module memory to avoid use-after-free of native transfers. Automatic recovery and complete flow validation remain required.

The unskipped opening exposed direct particle geometry port writes (first at matrix-scale port `0x0400046C`). The shared original particle drawing code now uses the existing native geometry commands for all its primitive, texture-coordinate, matrix, color and polygon operations. Particle math and resources are retained. Tests exercise the original texture setup, texture matrix, XY/XZ quads, zero-alpha handling and a visible billboard's color/polygon attributes on both native-host and ABI32 paths. Native-host sine/cosine data is generated from the original 4096 assembly pairs; the ABI32 path continues using its verified original data object.

`python3 ios/tools/check_native_engine.py --no-input --host-only` exercises seventy seconds of opening without synthetic keys, including the former particle failure. The report distinguishes input modes and leaves its completion gate unpassed. This run no longer traps, but capture success does not establish visual equivalence or complete-opening fidelity.

The rebuilt iOS 27 Simulator app was also allowed to run without input: at approximately 77 seconds it reached the original Ho-Oh title scene with star particles and no stopped-engine error. Both Simulator and iPhoneOS app builds succeeded. This verifies passage through the opening; it does not establish frame-by-frame fidelity or complete gameplay.

The original scripted home route now saves through `SaveGameNormal` to the 512 KiB image. `WaitFlashWrite` pumps native owner-thread IRQ replies while polling, preventing its completion flag from starving indefinitely. An isolated ABI32 check queues the actual original callback from a background thread, verifies it has not yet run, then requires the original poll to deliver it; ASan/UBSan and TSan runs pass. Existing native save round-trip, dual-slot recovery and corruption checks also pass.

With that actual image, `python3 ios/tools/check_native_engine.py --continue-load --host-only` launches a new native process and selects Continue through the original menu. It displayed trainer A and time 0:01, then restored the saved home position; the image SHA-256 remained unchanged. This verifies this native-host save/load route, not iOS lifecycle interruption during save or all game states.

On native builds, the main menu only starts optional DS beacon discovery when the existing PXI capability query reports a WVR service. The unavailable service previously led to the original wireless startup termination path when a valid save enabled the menu. Local DS wireless transport is still unimplemented; this guard does not claim networking success. Other explicit wireless entry points still require platform adaptation.

UIKit integration was also exercised through the actual landscape controls: a backed-up blank test image was replaced with the native checkpoint, Continue restored the room, a direction press moved the character, the original menu saved the changed position/time, and a fresh app process restored that position. One earlier UIKit Continue attempt reported an indirect-call validation error; its cause remains unproven and it did not recur in subsequent restore/save/restart runs. Trap logging now retains a native backtrace for diagnosis. Stability and save interruption testing remain incomplete.

Walking through the house exit subsequently reproduced an indirect-call error in `AreaMapAnimation_Load`. Its registered allocation callback accepted three arguments through an unprototyped pointer while its dispatcher passed four. The pool now has a typed four-argument loader, and the area callback explicitly receives the pool and animation instead of relying on their first-member layouts. The pool-list constructor returns its allocated object, arrays use element sizes, and animation allocation derives the map-data extent from the actual object layout.

The focused native/ABI32 regression calls the original public pool/area loading path for 0, 1, 2, 3, 254 and 255 map entries, checks allocation/initialization and releases every object. `--continue-walk-out --host-only` reads the checkpoint and attempts the original doorway transition. It passes the former allocation callback and currently fails later in `NNS_G3dGeSendDL` while rendering the outdoor map. This is a remaining geometry/display-list issue; outdoor exploration and the subsequent story are not verified.

The outdoor display-list failure was then traced to 6144 retained vertices before view-volume rejection. Geometry assembly now stages each primitive, rejects wholly clipped polygons before storing their vertices, and preserves triangle/quad-strip references across rejected polygons. RAM limits remain 6144 vertices/2048 polygons. Native/ABI32 tests submit 18000 wholly offscreen vertices, then visible geometry, and check strips re-entering the view and capacity rollback. Partially intersecting polygons retain their original vertices for the rasterizer's attribute clipping; exact clipped-vertex and winding-rejection RAM accounting is still incomplete. The original pixel renderer and its attribute interpolation remain in use.

The 70-second native-host checkpoint/walk-out run now reaches New Bark Town, renders the original exterior, and runs the neighbor/Marill movement without traps. This verifies this transition and initial event movement; the lab, starter selection, complete outdoor coverage and battles remain unverified.
